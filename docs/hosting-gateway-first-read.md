# Gateway authority and first read

The local Cloudflare twin can combine its authoritative generation check with the first actual R2 read batch for a supported cold fetch. Git still runs in the separate native Rust/Git process. This is a local workerd protocol experiment, not a portable Git codec or a deployed Worker.

`repository-host --cloudflare ... --view-cache cold` requests the exact `gateway_first_read` capability during its normal registration. `--gateway-first-read off` disables only that requested capability and is useful for a same-binary control. Warm hosts never request it. An absent acknowledgment preserves the ordinary legacy path; a present malformed or unsolicited acknowledgment fails registration after clearing all prior private capabilities.

An eligible request is an exact small standard Git upload POST with a known length in 1..128 KiB and at most 256 forwarded headers. Receive, discovery, warm, unsupported grammar, dirty recovery, missing lineage, oversized legacy chunks and response-cache hits use the ordinary path. Unsupported planning performs no service callback, recovery, Git command or materialization. Instrumentation counters describe planning outcomes; they do not fabricate service receipts.

## Request-local sequence

1. The public Worker strips private ingress and asks Native to plan. Native authenticates a versioned bounded frame and uses the existing history parser, lineage certificate, full/prefix selection and first-batch calculation. It releases the sequential HTTP handler when the planning response returns. No pending session map, object slot or lock survives that call.
2. The same Worker invocation directly dispatches one internal DO request. Inside the existing serialized service gate, the DO reads the actual manifest row before any GET. A changed generation returns zero GETs. A same-generation full-manifest fingerprint mismatch errors before GET. A match reads exactly the existing first batch in order using real R2 operations and existing GZBR framing.
3. The Worker accepts that actual DO receipt once, rechecks registration identity, then sends a signed continuation to Native. Native verifies the entire frame, the ordinary deterministic generation witness, original request identity and all returned chunk lengths and SHA256 content addresses. It rederives the complete current plan before consuming the owned verified first prefix once. Later batches use the unchanged bridge. All selected bytes are verified before installing disposable Git files.

The registration uses a separate 32-byte HMAC key with the same registration session as the generation-witness capability. Request, response and continuation use distinct signature domains. Signatures cover each complete bounded frame, including original request bytes and prefetched payload. The Worker rechecks its captured registration object after each asynchronous phase before proceeding. Native rechecks its current capability before consuming the continuation. The private routes are outside public repository routing; stateless nonces are request bindings, not replay protection against an operator with internal access/key material.

The canonical manifest digest includes generation, every ordered pack descriptor and representation, refs sorted by UTF-8 bytes, and ordered retirement garbage. It does not depend on JSON field order or JavaScript UTF-16 sorting. A Native publication retains a fixed authoritative published digest before its local successful-deletion cleanup, paired with the exact local digest and generation. Planning requires that local pair still match. Recovery refreshes it from an actual authoritative load; ambiguous publication invalidates it. The complete owning Option/struct storage is charged to the existing cache budget. This preserves full ordered-debt authentication immediately after compaction.

## Errors, cache identity and bounds

Generation change uses the already paid authoritative result and normal recovery. A local publication, changed certificate or new cache hit after a successful prefetch can discard paid bytes and take the ordinary fresh path; all work remains charged. Missing/corrupt/truncated data, invalid authentication, unknown receipts and ambiguous continuation transport errors never silently reread the first batch. Body failures with unknown consumed bytes mark accounting incomplete. Unknown SQLite rows remain null. Native never reimports the gateway's usage receipt.

Ordinary and reconstructed cache keys ignore only these named transport fields: Host, Connection, Content-Length, Transfer-Encoding, Accept-Encoding, CF-Worker, CF-Connecting-IP and the private fetch authentication header. The HTTP runner still validates framing before dispatch; original Git parsing headers are retained. The codec sets content length from the decoded body, never maps the two CF fields or Accept-Encoding into Git/CGI, and does not encode responses according to Accept-Encoding. Authorization, Cookie, Git-Protocol, Content-Type, Content-Encoding, Accept, User-Agent, custom fields, the deterministic generation witness and original body remain in the key. The authoritative generation is verified before serving a cache hit.

No caps increase: 128 MiB complete snapshot, 64 MiB incoming request, 16 MiB bulk payload plus 2,060 bytes framing, 256 batch entries, 32 MiB joint owning response/certificate/private-key cache, 256 response entries and 32 KiB lineage proof. The private frame is at most 18,410,368 bytes: 20-byte header, 1.5 MB metadata, 128 KiB original body and the existing maximum bulk frame. Payload buffers are transient and are not stored as objects or retained between requests. The raw frame is released after constructing its owned verified prefix.

## Validation and cost scope

The Rust correctness drivers are `tests/first_read_cloudflare.rs` and `tests/first_read_warm.rs`; ignored tests require explicit local origins, fresh artifact directories and an installed Wrangler override. They own only their checked isolated process groups and stop services on completion. The fault wrapper is test-only and records real attempts in addition to production receipts; it is not a benchmark backend.

The deterministic opt-in/out control proved one fewer external Worker-service request and one fewer DO request per activated real Git fetch POST, with identical authoritative reads, GETs, read bytes and Git responses. Observer statistics remain separately visible. This is a topology/correctness result. Fresh screened performance/cost receipts and all workload guards are required before any optimization decision.

Worker CPU, DO duration, SQLite monthly retention and external Native compute remain unknown. Extra Native planning/continuation HTTP and whole-frame HMAC work are not free in the complete bill. Full estimated cost therefore remains null; the frozen known-operation subtotal can improve without proving a lower complete cloud bill or faster Git service.
