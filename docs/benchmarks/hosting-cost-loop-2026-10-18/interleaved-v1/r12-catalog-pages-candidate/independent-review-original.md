1. **P2 — Numeric catalog corruption can prevent authoritative recovery, or remain hidden behind a valid aggregate.** `examples/repository-host/cloudflare/src/index.js:595–598` unconditionally applies `count()` to aggregate objects/bytes, fallback, and maximum peak inside `reloadCatalog()`. That function is called from the constructor and again before GC can reset the catalog. A persisted page with a valid BLOB and SQL `size = -1` therefore throws before a generation-checked GC reaches authoritative physical inventory or catalog replacement. An unsafe positive SQL size or peak can produce the same result; an invalid fallback also blocks opening. Conversely, a negative per-row size can be masked by another positive row in `SUM(size)`, leaving a safe aggregate and `catalogCertain = true`; mutation of a different valid page can then use an incorrect live-byte total. These are source-derived counterexamples, not new probe results.

   The intended recovery contract explicitly permits replacing corrupt metadata without first decoding it. Preserve individually valid durable peak witnesses, the process floor, and the complete physical pre-delete inventory; mark invalid metadata uncertain without making constructor/GC entry impossible. A corrupt positive fallback needs explicit treatment because `MAX(existing, H)` preserves it. Aggregation must not overflow in SQL before invalid metadata can be classified. Actual negative/unsafe SQL size, peak and fallback fixtures, mixed valid/invalid rows, and full reopen/GC evidence are missing from frozen R12. Existing `unsafe-size` changes encoded member bytes while leaving the SQL row size safe; `aggregate` uses the safe value 48, so neither covers this defect. Root and implementer were notified; the implementer acknowledged the scope, but no fix is part of this reviewed SHA.

   Recovery cannot reconstruct an arbitrary historical peak after every trustworthy witness for it was corrupted or lost. Document that limit separately from recovery of membership/live totals and from the existing R11 unrecorded-upload crash gap; do not certify a lower reconstructed historical peak as the lost original value.
