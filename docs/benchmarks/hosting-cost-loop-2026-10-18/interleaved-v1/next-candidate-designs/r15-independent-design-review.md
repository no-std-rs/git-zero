# Gateway authority plus first read: independent design review

**Disposition: a concrete, conditionally viable next experiment, not a measured saving.** A stateless Native planning call, one internal gateway-to-DO authority-plus-first-batch call, and a Native continuation can remove one external Worker request and one DO request on an eligible cold fetch miss. It preserves the existing authoritative generation read and the exact existing chunk selection. It does not require a session table, held Native lock, object cache, stale lease or different Git object closure. The additional Native HTTP/CPU work and latency remain unknown until measured. A design that instead makes Native call a combined external authority/read service saves only a DO call and is **not** the candidate reviewed here.

Read-only review at frozen source `5c616c23469fff9c7f64789dc29dc640bbc0dfc1`: Worker gateway/service dispatch and DO gate/read handlers; Native dispatch, cache key and cold view selection; bridge generation witness/bulk framing; repository selected snapshot materialization and `VerifiedChunks`; the Rust sequential HTTP runner; auditor preparation and `/tmp/git-zero-gateway-first-read-hypothesis-counts.json`. No repository edits, build, runtime, probe, CI action or benchmark was performed. This report does not inspect incomplete new screen results or authorize implementation in the frozen primary.

## Why the topology can save both calls

Today the public gateway invocation calls `generationWitness()` -> `dispatchService()` -> DO manifest GET internally, so that authority check costs a DO request but no second external Worker request. Native then calls `/_services/blobs/read` through a separate external Worker invocation -> DO for its first read batch. In the proposed normal path, the same public gateway invocation calls Native locally to plan, then itself calls one DO method that checks authority and reads that first batch, then sends the result to Native locally. There is one public Worker invocation and one DO invocation for those two tasks. No new `/_services` HTTP callback may occur for the preflight, authority or prefetched first batch.

The earlier sample-zero count of 48 actual-byte fetch misses in each cold profile, zero in warm profiles, gives **96 × $0.00045 = $0.0432 gross** under the frozen 1,000-repetition/four-profile pricing. This is conditional old-trace arithmetic, not a fresh count, net result or acceptance. It is large enough to merit an experiment if the protocol gates pass; new counters must identify actual activation and fallback costs. SQL reads can remain one authoritative matched row, actual GET count/bytes are unchanged, and later bulk callbacks are unchanged. Native preflight and continuation network/CPU work are not free in the complete bill: those dimensions remain UNKNOWN.

## Eligibility and immutable request identity

Opt in with a distinct exact registration capability tied to the current witness registration session. Limit initial use to cold Native, exact standard `POST /repo.git/git-upload-pack`, bounded original request body **<=128 KiB**, supported protocol/MIME/header grammar, a clean Native view, validated manifest and a nonempty planned first batch. Warm mode, discovery, receive, empty/unknown/oversized grammar, dirty recovery, missing capability and unsupported legacy chunks take the ordinary gateway path. Preflight itself must not recover, call services, materialize, change refs, mutate certificates, migrate state or run Git.

Represent the original request by its method, forwarded ASCII target, exact original body and canonical normalized header list, including every field affecting current Git/cache behavior. The public gateway strips all existing private prefixes, generation/retirement proofs, token and host exactly as today. Transport-only preflight/continuation authentication headers are never allowed to become original semantic headers. Bound headers using the existing 64 KiB aggregate/8 KiB line constraints; reject duplicate/conflicting framing. The gateway buffers only an eligible small POST, not an arbitrary receive body.

**Important cache trap:** `NativeHost::cache_key()` hashes every header, including the current deterministic generation witness. Random nonce/MAC/continuation headers inserted into that map would silently turn cache hits into misses. Construct the exact same ordinary logical request for planning and continuation, with the ordinary deterministic witness for the checked generation where applicable; strip private transport fields before dispatch/cache hashing. Alternatively explicitly normalize private transport headers out of the cache key in both ordinary and optimized paths, with regression evidence. A cache hit found during preflight is merely a planning hint: it cannot be returned before fresh DO authority. Initial implementation can return `Unsupported(CacheHit)` and use the ordinary generation witness + cached-response path, with zero prefetch GETs. Cache insertions/evictions after planning are rechecked on continuation.

## Private protocol and no-held-lock sequence

Use private Native endpoints outside `/repo.git`, handled explicitly by the Rust listening wrapper, for example `/_git_zero_internal/fetch-plan` and `/fetch-continue`. Public repository routing must not reach these routes. Requests/responses use exact versioned typed envelopes with unknown/duplicate fields rejected; bounded magic/version/length-prefixed binary framing avoids putting a 16 MiB batch into headers or base64. Authenticate both directions with a registration-scoped key using separate HMAC domains for plan request, plan response and continuation. Reusing the private generation-witness key with distinct domains is technically possible, but an explicitly negotiated separate key/session is clearer. Do not use the retirement-absence key: it is deliberately unavailable to Native.

1. **Gateway -> Native plan.** Capture the current registry entry identity, allocate a random request nonce, hash the canonical original request, and send a signed bounded planning request containing session, repo, nonce and original logical request. Native verifies before consulting its host. It acquires only the normal bounded handler access, checks eligibility/clean state/cache, validates the entire snapshot, and invokes the **same** current full/prefix selection function and first `bulk_batch_len` algorithm. Do not duplicate the history parser in Worker. Unsupported means no service or storage I/O. A supported response contains request hash, nonce, generation, exact manifest fingerprint, selection fingerprint/scope, and ordered first-batch `{key,len}` entries; at most 256 entries and 16 MiB payload, with existing framing bounds. It is signed and contains no object bytes. Native returns, releasing handler access. It retains no pending plan/session/object buffer.
2. **Gateway -> internal DO.** Verify Native response authentication, schema, bounds, request binding and unchanged registry identity. Call `dispatchService()` directly with required receipts and one new internal authority/read operation. This is not an HTTP fetch of the Worker service route. The DO validates the complete requested batch/expected bindings before I/O and enters the existing serialized service gate once. It performs one actual authoritative manifest read. If generation or manifest fingerprint differs, it performs **zero GETs**, returns a typed `GenerationChanged` with actual checked generation (and optionally bounded manifest), and the real authority receipt. On a match it performs the exact ordered first batch using the current real `operation("r2_get", ...)` accounting and current missing/length/body-failure semantics. It returns a bounded GZBR payload plus bound authority metadata. Do not recursively invoke DO `fetch()` to reuse the read handler: that would double-count or deadlock; share its validated read implementation inside the single callback.
3. **Gateway -> Native continuation.** After accepting the real DO receipt **once**, send a signed continuation envelope containing original logical request, session/repo/nonce/request hash, checked generation, manifest/selection/batch fingerprints, actual authority result, and raw first-batch frame when present. Include a hash of all continuation payload bytes in its signature. The original body, metadata and <=16 MiB+2,060-byte bulk frame fit within the existing 64 MiB incoming cap; reserve a fixed documented envelope overhead and validate total lengths before allocation. No blob bytes persist outside this request. Recheck registry identity after each await; a changed session suppresses optimized continuation and must not be silently substituted with a new registration's authority.
4. **Native consumes.** Verify framing and HMAC before trusting the envelope or files. Recreate the logical request and ordinary generation witness; compare exact body/headers/request identity. Under handler access, recheck clean/current manifest, view identity, certificate/scope, cache outcome and **rederive** the exact same selected pack sequence and first batch. A valid matching envelope supplies a typed `VerifiedChunks` first batch to this one selected snapshot materialization call, followed by the ordinary remaining batches. No global `HttpServices.pending_prefetch` slot, mutable map or cross-request stash is needed. All selected descriptor graph checks and every selected SHA/length verification still complete before disposable native files are installed, exactly as now. Then run the existing native upload-pack and cache insertion.

The manifest fingerprint must use a fully specified canonical encoding shared by Rust/JS, not `JSON.stringify` versus arbitrary serde field order. A versioned length-prefixed binary encoding of generation, UTF-8-byte-sorted ref pairs, ordered full pack descriptors/chunks and ordered garbage is sufficient. Preserve duplicate/live-key and exact-length checks. Include the selected pack positions/scope and exact first-batch order in a separate fingerprint; generation alone does not authenticate a request/selection. Actual public inputs never supply the plan. The DO need not implement history closure: trusted Native produces the plan and Native rederives it before use; all reads are still scoped to the trusted routed repository.

The Rust HTTP runner currently processes one complete request at a time using `FnMut`; that makes the two-phase protocol practical without holding a mutex across a DO call. It is not a transaction spanning both requests. Another push or read can run between plan and continuation, so matching must be checked again. Keep only request-local bounded envelopes and registration metadata already bounded per repository, not an unbounded nonce registry. Public clients cannot replay a private continuation: private routes require the registration authenticator, gateway strips private ingress, and a new public request always performs new authority. Do not advertise stateless nonces as replay protection against an adversary who already possesses the internal registration key; that key is the trusted boundary, as it already is for generation witnesses.

## Paid fallbacks and errors

- A typed unsupported preflight occurs before any DO/GET and falls back to the existing gateway authority path. Do not perform Native authority recovery in preflight. A preflight transport/auth/malformed error is an error or a tightly specified pre-I/O fallback, not permission to accept an unsigned plan.
- A DO generation mismatch reads authority but no objects. It can supply the usual signed generation witness to ordinary Native dispatch, which detects any local mismatch and performs existing recovery. Do not issue a second gateway authority read merely out of habit; if another local change requires a later authority read it is actual paid fallback. Include that path in measurements.
- If Native/certificate/request state changed after a successful paid first-batch read, discard the paid prefetch, then follow the explicitly defined ordinary fresh dispatch/recovery path. All previous calls and bytes remain in the receipt scope; do not label this `Unsupported` or subtract them. An intervening local publication must never consume an old batch under a new plan. A new Native response-cache hit may simply discard the paid bytes and serve only after the checked authority semantics remain valid; count the waste.
- Missing/corrupt GET bytes, invalid batch lengths/SHA/frame, missing/unknown receipts or ambiguous DO/continuation transport failures are errors, **not** a signal to fetch the same first batch again. Mark accounting incomplete where its consumed bytes are unknown, as existing code does. Retrying read-only I/O might be safe for data, but would violate the intended receipt/attempt accounting if hidden. A later independently initiated request is counted normally.
- Existing freshness linearizes at the authoritative DO read; it is not a lock across the entire Git response. A publication after that read may delete chunks before later batches, which already can cause a truthful read failure. The combined gate must not worsen this by accepting an old plan on a mismatching checked generation. It must not claim new snapshot-retention guarantees without implementing/pricing them.
- The gateway alone accepts and merges the actual DO usage header. Its continuation may carry an authenticated summary for validation/diagnostics, but Native must never feed the same receipt back through `acceptReceipt()` or invent a second service callback. Count one DO request, one `manifest_get`, each actual GET attempt/byte once, any errors, constructor/reopen work and all later service calls. Preserve NULL SQL and full-bill unknowns.

## Memory and integrity integration

Pass an owned `Option<VerifiedChunks>` or equivalent private first-batch argument directly into a new internal selected-snapshot read helper. Validate it against the **exact prefix of the flattened selected chunk list**, including repeated keys/order, and consume it once. Call the existing store for the remaining suffix with the same original batch boundary; inserting a generic key-value cache would change repeated-key semantics and invite cross-request reuse. Do not populate the ordinary blob store or retain prefetched objects after materialization.

Original request+batch framing is transient incoming I/O, as existing bulk response bytes are transient, not a new retained object cache. Move/reuse owning buffers where possible; account every new retained plan/metadata/proof allocation in the joint 32 MiB budget and evict before allocation, including any pending continuation representation held by the host. A convenience field storing up to 16 MiB across requests must not be called free transient memory. Keep <=256 batch entries, <=16 MiB payload, <=128 MiB complete snapshot and unchanged 32 MiB/256-entry response-cache limits. Existing full/prefix closure, pack/index validity and strict fsck/archive requirements are unchanged. This protocol offers no authorization to select fewer history packs or omit refs.

## Required first controls and decision

Before a screen, use a Rust-driven actual Worker/DO/R2 test with source hashes and real receipts to prove a cold supported miss has one fewer external Worker request and one fewer DO request with identical ordered GETs/bytes, exact manifest/refs and full fsck/archive. Exercise one-batch and multi-batch/full/prefix reads, both cold sizes, unchanged warm/cache-hit/discovery/receive traffic and default Git client requests. Require activation counters distinguishing supported plans, unsupported before I/O, generation mismatch, consumed first batches and paid discards; a dormant capability is not a result.

Test interleaved plan -> push -> continuation; plan -> external generation change -> DO; DO read -> local push -> continuation; matching generation but changed view/certificate/cache; registry replace/unregister/eviction; direct/public spoofed private headers/routes; stale/replayed wrong-body/target/repo/session/selection envelopes; Unicode refs/canonical fingerprints; malformed/duplicate/oversized JSON and binary frames; exact 16 MiB+framing boundaries and <=128 KiB original body. Confirm no lock is held across a Native-to-Worker callback and no nested DO fetch. Test failed/missing/truncated GET, corrupt bytes, unknown rows/missing receipt, dropped continuation and paid fallback, with no hidden retry and each actual attempt counted once. Verify final memory/cache, storage, no read-side writes and actual first-batch objects are not retained as cache.

If these controls pass, the candidate has concrete >1% gross potential and warrants a clean committed/pushed implementation, independent source/fault review and the authorized fresh two-pair four-profile screen. Net ≥1% cost and latency/storage/byte guards still need measurement, followed by the mandatory five fresh original-R1/final pairs. If the protocol adds an external Worker authority/preflight callback or cannot consume the prefetched first batch without re-reading it, reject that implementation rather than credit the $0.0432 hypothesis. No global cost floor or stopping conclusion follows from this review.
