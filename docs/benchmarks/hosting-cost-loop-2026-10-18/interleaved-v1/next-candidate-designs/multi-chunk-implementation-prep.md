## Pool, admission and pruning

Use a deterministic bounded Vec/array, maximum32 entries. Index0 is the anchor; remaining entries retain insertion order. Descriptor lookup can scan at most32 entries, avoiding an unbounded map. Charge actual backing capacity and conservative allocation overlap before any growth; an inline array avoids heap-capacity growth but still has fixed state bytes to account. Store each exact key+length identity once; repeated selected occurrences can clone one immutable handle without charging the same physical payload twice. Preserve existing rejection of contradictory malformed metadata.

A newly required ordinary verified GET is offered in original selected-descriptor order after its actual receipt and integrity proof are valid. The callback is synchronous and cannot issue I/O, mutate authority or validate a pending publication. Keep repository/cache field ownership split so the visitor does not need a second payload cache, global stash, unbounded candidate list or hidden copy. Admission of that existing Arc is allowed only when both entry and actual owning byte limits fit **without evicting any live cache entry**. Otherwise count a rejection and continue productive reconstruction. Never evict an earlier resident merely to fit a later scan item. No PUT/import, startup/recovery, stats/observer, warm-mode, speculative, dummy or fixture-key admission. Warm mode retains no cold secondary pool.

Use common optional soft headroom for secondary admission only if needed to preserve response reuse: the audit's14MiB response/1MiB control figures are heuristic inputs, not retained allocations, proof that actual control fits, or hard response caps. Actual joint usage always wins. Do not reserve/allocate/count nonexistent14MiB storage or reject an otherwise eligible <=16MiB response at14MiB. If actual owning capacities reject different candidates, retain the resulting misses rather than forcing the modeled338.

Prune only against a complete validated **authoritative current Full manifest**, installed after a strict confirmed winning publication, or after successful ordinary full authoritative recovery that has resolved ambiguity. Exact reachable descriptors come from all current packs, never selected projections or garbage/deletion outcomes. No prune from proposed `next`, attempted/stale/ambiguous CAS, observer refresh, witness-only external-generation notice or a projection's subset. Existing `receive_transaction` reaches `RetiringCas::Published`, installs `self.manifest = next`, then updates local garbage/authority; place the successful-publication prune after the confirmed full installation, before later cold use. A confirmed publication with partial physical deletion may prune logically unreachable entries, while dirty reconciliation and all actual deletes remain required. If subsequent native-view setup fails, conservative failure cleanup may drop the pool; do not call that confirmed-retirement pruning.

If a pruned anchor disappears, promote the oldest remaining eligible resident to index0 without allocation. With no resident left, the next actual GET becomes anchor only if it fits. Never evict live secondaries to fit a new larger anchor. Distinguish prune, required-memory pressure, reset/error cleanup and capacity rejection in diagnostics. Cache contents are never generation, durability, retirement or GC witnesses; every use still requires exact current authenticated selected membership.
