### Concrete representation and implementation recommendation after review

Independent review is `/tmp/git-zero-fused-metadata-design-review.md`; its disposition is conditionally viable. Prefer **one nullable private root BLOB column on `repository_state`**, not an unbounded private manifest field or duplicate root ownership. Use a new dedicated envelope: magic 4 bytes, version u8, count u8 in 0..32, historical peak u64 LE, applied generation u64 LE, then sorted unique `(digest[32], size u32 LE)` entries. Header is 22 bytes and maximum is **1,174 bytes**. Validate exact length, safe peak/generation and size sums, each size ≤16 MiB, sorted unique digests and coherent ownership before mutation. Count zero is valid in this private singleton envelope and retains H/acknowledgment after emptying the store; it is not an ever-growing set of empty routing pages. Do not pass count zero to the current nonempty GZCP decoder. Null means ordinary table-page ownership; corrupt/multiple ownership is dirty, not silently double counted.

Introduce one catalog-owner abstraction used by **every** lookup, inventory, reload, update, retirement, peak witness, debt flush, split and GC path. A co-located nonempty root is the sole `pages/` leaf and cannot coexist with table child pages; legacy exact-key rows can remain mixed only with the existing duplicate detection. A count-zero envelope may retain H beside table child pages but must not be treated as an active overlapping root. After a split, root membership is cleared atomically while bounded child rows are installed; the envelope may retain only H/ack. A later promotion requires a charged check that no table child page exists. Do not add an unbounded directory/cache.

`catalogLookup` currently performs 66 exact-key/ancestor probes in groups of four UNION ALL terms (`index.js:792–818`), deliberately avoiding temporary IN-row billing. The owner abstraction must include the one singleton root read and still inspect possible legacy/ancestor overlaps. Indexed catalog-row reads, schema discovery, constructor inventory, promotion/demotion and state generation reads are actual measured cursors; no free cache or read-count assumption is justified. A shared `SELECT generation,manifest,<root>` may avoid a redundant matched-row read, but do not claim that saving before cursor measurement.

Fast-path eligibility is decided before physical upload: distinct registration capability, complete valid bounded root ownership, current exact catalog or resolved debt, selected next root ≤32, no uncoupled pending rows and no required split/migration. An absent schema or eligible normalized/v1/table-root store may take a **separately charged** bounded migration first; do not mass-migrate legacy rows or write from a read. Fresh older-provider namespaces retain their old DDL path. New common Worker code must understand durable co-location after capability/session loss or older-Native reconnect; Worker rollback unable to decode the new representation remains unsupported. Existing valid large/oversized external CAS is preserved by updating the same owner's row, or by paid atomic demotion followed by ordinary CAS, never by returning a new rejection.

Inside the synchronous transaction, read the actual current row/generation and perform one INSERT/UPDATE of that row. On a match, store next generation/manifest plus new root/H; on a mismatch, store **unchanged current generation/manifest** plus uploaded root/H, return stale after sync. Ordinary generic PUT writes only the catalog fields while preserving manifest/generation; ordinary CAS writes manifest/generation while preserving catalog fields. Missing initial row is generation zero with canonical empty manifest. No caller-supplied catalog state is accepted. Keep manifest shape and receipt bodies unchanged, and name/count the actual CAS attempt once.

**Critical acknowledgment:** when a new fused publication replaces generation g with g+1, the coupled root's acknowledgment certifies **the resolved prior debt generation g**, never g+1 before g+1's real DELETEs happen. After publication its new debt must remain visibly unapplied. Stamping g+1 early would let reopen treat newly retired keys as already absent. Same-key debt still obtains its prior acknowledgment in a separate durable pre-PUT barrier; this exception is not removed to hit the row target. Unknown/partial debt, unrelated table owners, legacy pages and no-PUT CAS retain their current paid flush semantics.

The pre-CAS catalog sync is not logically necessary to prevent a **durable winning manifest without a durable peak** if both are stored atomically and a successful shared sync still gates DELETE/clean reply. Current `blockConcurrencyWhile` serializes the full service operation (`index.js:1350–1392`), so another service request cannot observe a half-constructed coupled row. SQLite row/transaction atomicity must remain an explicit supported storage assumption, as it already is for ordinary CAS. This does replace the stricter intermediate state in which today's catalog has already synced before CAS is attempted.

On a failed coupled SQL transaction after a physical PUT, the result maps to today's **PUT-before-first-catalog-write failure**: actual PUT is charged, no successful upload/CAS/proof is fabricated, the catalog is arbitrary-uncertain, Native stays dirty, and generation-checked physical GC inventories the orphan and preserves the whole pre-delete physical peak before destructive work. A failed transaction must not leave a new durable generation without its root/H; ambiguous sync may have committed the entire row, so recover current generation rather than retry publication/deletion blindly. A lost successful reply can likewise have a durable winner and performed deletes. This does not supply a stronger arbitrary-direct-caller/restart repair guarantee than the existing orphan window; if preserving the distinct pre-CAS synchronized state itself is a non-negotiable requirement, this replacement is not eligible. Stale return is stronger than generic error: **only return stale after the uploaded root/H has actually synced**.
