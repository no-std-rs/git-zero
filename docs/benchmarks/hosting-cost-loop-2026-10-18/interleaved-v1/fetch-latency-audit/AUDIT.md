## Exact timer and request scopes

Paths below are relative to `/tmp/git-zero-hosting-cost-loop/examples/repository-host`. The audited `http.rs`, `cloudflare.rs`, and `socket_rpc.rs` are byte-identical between R18 source commit `f1ba8f548507dca1e5ab78e5c5d20d8360ecee21` and the primary checkout. Worker files match the archived expected hashes. `7f41db4407963ed04e6cbe19556b1416633caf18` is the recorded Worker source tree identity, not a commit whose whole repository should be diffed. Native cache-policy changes exist after R18; both the archived R18 code and current code were checked for the relevant timer boundaries.

* `src/native.rs:1559–1569`: response-cache misses call `fetch_read_view` before starting `Instant`, then time only `native_read` and add elapsed to `upload_codec_seconds`. In R18 the same boundaries are lines 1508–1511.
* `src/native.rs:2208–2220`: authenticated gateway continuation materializes the selected view before `Instant`; lines 2217–2219 time `native_read` only. R18 equivalents are lines 2066–2077. The worst retained row has `gateway_read_consumed=1`, so this continuation scope is relevant.
* `src/native.rs:993–997`, `298–369`, `37–71`: `native_read` calls `git_rpc`, whose identity path invokes Git stateless upload-pack and buffers stdout. `command` writes stdin on a scoped thread and waits with stdout/stderr capture. The timer includes process spawn/wait/output collection and small codec-path work; it is elapsed wall time, **not CPU**. Requests with haves select `pack.window=1`. Encoded/invalid-content-type paths can instead invoke `http_backend`.
* `src/http.rs:133–160`: serial accept, full header/body read, synchronous handler, then header/body writes. There is no existing phase timer here. Body writes occur after the Native codec timer. `let _ = send(...)` preserves listener availability on disconnect but discards write-error evidence. Thirty-second read/write socket timeouts are not a total request deadline.
* `cloudflare/src/index.js:554–574` and `first-read.js:150–193`: cold eligible requests can buffer a small request, plan with Native, perform authoritative first-read, buffer its bulk response, sign a continuation, then fetch Native again. The normal path obtains a generation witness through a DO manifest request before forwarding to Native. Awaiting `fetch` yields response headers/stream; it does not demonstrate downstream body completion.
* `src/native.rs:853–944`: view materialization removes the prior disposable view, resolves/verifies selected chunks, initializes Git files, writes pack/index data and refs. Those costs are outside the codec counter. Warm fetches bypass that reconstruction when the full view is current.
* `src/cloudflare.rs:573–738`: service callbacks try an eligible socket route, otherwise open a new HTTP connection and read the complete framed response. Connect, request writes, status/headers, and body have no separate elapsed/error-stage records. HTTP callback timeouts are 60 seconds per socket operation.
* `src/socket_rpc.rs:201–215`: only bulk blob reads, bulk upload-retire, and chunk PUTs are WebSocket eligible. The client waits for response segments and terminal, then ACKs; attempted RPCs are not replayed after transport failure (`133–197`, `400–438`). Worker `service-socket.js:104–139` first completes/buffers the service result and sends bounded segments with an ACK gate. Counts are not timing measurements.
* `src/bin/hosting-bench.rs:273–320`: client elapsed wraps `Command::output()` for Git, including its transport and local processing; `/usr/bin/time` supplies client CPU/RSS when present. Post-fetch fsck/archive checks are outside that timed command (`943–988`). Before/after observer calls are also outside the command measurement. No retained per-packet curl/Git timestamp trace was found for the audited R17/R18 fetch samples.

Consequently neither a small codec counter nor Wrangler's header-oriented timing identifies the remaining wall-time phase. Serial service can cause head-of-line waiting if requests overlap, but overlap was not demonstrated here. A concurrency rewrite, timeout increase, retry, body buffering change, or Git pack-policy change is not justified by these inputs.

## Latest-24 observer failure

The retained Joint source matches its source seal: `native.rs` SHA-256 `59d2e8ed53ba8d15c2eb99aea5b7aeb18a31111715ded1c4265961b6851e2cde`, test helper `c2efb9c0759ef57c2e9dce36f40a89f7381d00c1fe8ff376c2b11e85e234048a`.

`/tmp/git-zero-joint-first64-multi-01/host.log:4` reports `statistics failed: Resource temporarily unavailable (os error 11)`. `latest-24.headers` records a 200 response with Content-Length 55000637; the following `latest-24-after.headers` records 503 with Content-Length 17. The actual latter response body is absent. Its content must not be reconstructed from the source literal.

In Joint `src/native.rs:2280–2362`, `/metrics` is a handled statistics route. Unlike `/_object-stats`, it does not recover/materialize a repository or inventory Git objects. It obtains socket diagnostics, then calls `services.usage()` at line 2342. `HttpServices::usage` calls ordinary HTTP `GET /_services/metrics`; that route is not socket eligible. The propagated OS error is consistent with I/O in this callback path; the source does not identify whether connect, write, status read, header read, or body read failed. It does not prove a 60-second timeout, disk exhaustion, or Native exit. The response and catch path establish a handled request failure, not a process-exit event. Wrangler has repeated `Network connection lost` entries across otherwise successful steps; without correlation/timestamps these do not identify the failing callback stage or establish causality.

There is one proven test evidence defect. In `tests/multi_chunk_cloudflare.rs:13–21`, `run` uses `native::command`, which discards failed process stdout and returns stderr-only error (`src/native.rs:66–69`). `request` calls this helper at line 101, before saving body at 102. Thus curl `--fail-with-body` can return its error body on stdout but the helper loses it on exit 22. The narrow correction is request-specific raw output capture, saving bounded stdout/body, stderr, status and headers before rejecting. Preserve the old failed artifacts. The R20 owner is already assigned this fix; this audit implements nothing.

## Minimal meaningful Rust-only diagnostic design

This is a design, not a request to restart the main benchmark. Use one isolated diagnostic worktree and a Rust runner owning all child lifecycles. Keep the approved Native R19, common Worker, Git executable, config, logical fixture and request bodies fixed. If instrumentation is needed, apply identical opt-in observational HTTP/process hooks to diagnostic baseline and candidate copies. Do not edit main reports, objective, cache rules, sample definitions, receipts or scoring. Diagnostic phase times remain unpriced and never fill CPU/duration billing nulls.

1. **Retain failures first.** Complete the already-assigned request helper correction. Save status, headers, bounded raw error body, stderr and child status before interpreting success. Capture service error route/stage, `ErrorKind`, `raw_os_error`, bytes completed and elapsed. Preserve pre-failure counter snapshot; a failed final observer means counters are incomplete, never zero.
2. **One real path, no new echo.** Select two sealed real fetch cases: cold64 generation-16 historical no-haves (worst retained key) and warm16 generation-32 historical no-haves (zero-R2 tail). Add one seeded historical-have case only if both first cases fail to discriminate. Replay each at most twice on independently initialized copies, preserving warmup/sample identity. Use actual Git fetch through the production gateway first. Preserve body framing/Expect behavior. Do not add a public correlation header: `cache_key` hashes non-transport headers and first-read authentication fingerprints logical headers. Correlate by isolated one-client request order, existing logical request hash, method/path, and body length/hash.
3. **Native event ledger.** Aggregate per-read counts/max waits in memory; emit bounded one-row-per-request records after completion/error. Record monotonic accept, header/body completion, handler begin/end, view-read/materialize begin/end, Git child spawn/exit, response header/body write begin/end, byte counts and write errors. In `HttpServices::call`, record each route/transport, connect, request-write complete, response-header/body complete or precise failed stage; for WS include open/send/first segment/terminal/ACK. Do not log token, secret headers or object payloads. Record request IDs plus host boot ID and a common OS monotonic clock so all Rust-process events can align without assuming realtime clocks are stable.
4. **Measure CPU independently.** A Rust child supervisor must drain stdout/stderr concurrently and obtain actual child usage (for example Linux `wait4` for the owned Git child), covering upload-pack and its descendants; preserve status, byte counts and hashes. Record Native thread/process CPU using an OS CPU clock and wall separately. `wait_with_output` elapsed, `/proc` ticks without a validated scope, and client CPU cannot substitute. If exact child accounting is unavailable, keep server CPU null and still use phase wall times. The same hook applies to reference Git for diagnostic comparison; no measured speed claim comes from the instrumented copy.
5. **Client boundary only if needed.** The Rust runner can retain bounded Git Trace2/curl-without-data diagnostics from the real client, including request/upload completion, response first byte/body completion and child exit. If these do not expose body EOF distinctly, use a Rust HTTP client for one exact saved Git POST through the same gateway, hashing and fully draining the response, then validate its pack against the sealed want/tree. This is a separately labeled diagnostic control, not a timed Git benchmark replacement. Do not bypass the gateway or skip callbacks/receipt collection. A slow Git-only case with a fast complete raw body suggests client-side negotiation/indexing/scheduling; a fast Native write with delayed client drain points between these boundaries, but still does not name the exact TCP/runtime cause.
6. **Discriminate, then stop.** Long child CPU plus child wall supports Git work; long callback phase localizes service/transport waiting, requiring its stage/bytes/error; long local materialization with fast callbacks localizes verification/filesystem work; fast handler but long write/drain localizes post-handler delivery; long pre-handler read localizes request intake. If no tail recurs, report non-reproduction and do not infer a remedy. Max two replicas per initial case and an explicit time/output budget prevent an open-ended diagnostic loop.

GO prerequisites: active all-four review complete; exclusive runtime owner and ports; a separately authorized diagnostic scope; sealed sources/binaries and copied fixture with matching want/tree; no access to active author processes/state; approved capacity and location for any future build/data (do not assume `/dev/shm` authorization for this audit); bounded output with a free-space floor; failure-body capture verified; a deterministic Rust framing check for Content-Length, chunked input, partial reads, premature EOF, and disconnected output; independent CPU scope validated or null. A later proven production fix must be applied symmetrically to baseline/candidate, frozen and fully rerun under the unchanged acceptance rules. No shadow-server work is included.
